Candidate 01

Deepen Automatic correction strategy assembly

Strong ports & adapters

src/local_text/config.py · src/local_text/app.py · src/local_text/cleanup.py
tests/test_app.py · tests/test_cleanup_router.py · tests/test_cleanup.py

Problem

One Automatic correction strategy spans configuration parsing, app-local validation and disclosure, adapter construction, route policy, and correction authority.

Solution

Consolidate strategy validation, disclosure, adapter assembly, and routing construction in one deep module; keep correction authority separate inside Cleanup.

Benefits

  • locality: assembly in one module
  • leverage: one strategy interface
  • tests stop inspecting app state
ADR-0001: compatible only while correction authority and routing remain independent. A per-mode route chain would contradict the decision.

Deletion test: removing the app-local configuration helpers merely spreads their conditionals into app construction; removing sequential routing spreads deadlines and failure policy across callers. Deepen the former around the latter.

Candidate 02

Deepen the Evidence Collection transaction

Strongports & adapters

src/local_text/static/app.js · src/local_text/app.py
src/local_text/evidence_collection.py · src/local_text/evidence_package.py
tests/test_evidence_collection_tracer.py · tests/test_evidence_package.py

Problem

The no-exposure-before-judgment invariant spans browser state, app orchestration, frozen observations, package writes, correction input reconstruction, and publication receipts.

Solution

Let one Evidence Collection transaction own freeze through confirmation, verified persistence, frozen correction input, and publication authorization.

Benefits

  • locality: invariant in one module
  • package remains an adapter
  • tests follow the transaction
ADR-0001: keep Evidence Collection independent of ordinary Smart correction and preparation choice.

Deletion test: EvidenceCollection already concentrates lease and storage rules; deleting it spreads those rules. The shallow part is the app orchestration around confirmation and publication, which should move inward.

Candidate 03

Concentrate outgoing selection and publication

Worth exploringin-process

src/local_text/static/app.js · src/local_text/state.py · src/local_text/app.py
tests/test_app.py · tests/test_targets.py

Problem

The browser derives the outgoing snapshot, the state model rechecks only part of it, and the app separately authorizes Evidence Collection publication.

Solution

Move selection, authorization, and revisioning behind one deeper publication module; callers provide facts rather than a derived state record.

Benefits

  • interface loses derived fields
  • locality: selection rules converge
  • tests assert publication outcomes
ADR-0001: preserve explicit Smart failure to Original; never hide a mode change inside publication.

Deletion test: deleting OutgoingStateStore moves little beyond locking and revisioning into the app module. Most complexity already lives in callers, so the current module is shallow.

Candidate 04

Deepen the Target lifecycle module

Worth exploringlocal-substitutable

src/local_text/targets.py · src/local_text/target_store.py
src/local_text/target_adapter.py · src/local_text/app.py · src/local_text/static/app.js
tests/test_targets.py

Problem

The app module owns operation order, generated previews, artifact observation, durable errors, and synthesized Target state.

Solution

Consolidate Target lifecycle operations and state synthesis in one deep module while retaining storage and filesystem adapters.

Benefits

  • locality: lifecycle order converges
  • adapters keep real seams
  • route tests stay caller-facing

Deletion test: deleting TargetStore merely moves persistence into app.py; deleting generation or the artifact adapter spreads safety rules. Deepen lifecycle orchestration without erasing the real adapter seams.

Top recommendation

Deepen Automatic correction strategy assembly

It is the hottest recent path, offers the highest leverage, and creates locality around ADR-0001’s separation of correction authority from fallback routing.
